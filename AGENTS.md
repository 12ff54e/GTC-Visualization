# Repository guide

This repository contains GTC Visualization, a Node.js and Express application for exploring Gyrokinetic Toroidal Code output. The server scans configured output directories, parses simulation files on demand, and serves Plotly figures to the browser.

## Development commands

```sh
npm install
npm test                         # build development assets and start nodemon
npm run pack-client              # build browser code from client/
npm run pack-server              # build server-prod.js
npm run pack-custom-plotly        # rebuild the trimmed Plotly bundle
npm run validate-input-parameters
npm run test:batch               # run the listed non-real-data test suites
npm run test:theme
npm run pack                     # build all release assets and create tarball
```

Node.js 22 or later is required. Building the FFTE WebAssembly binary additionally requires Emscripten; the checked-in browser assets can be used when FFTE itself is unchanged.

## Application flow

1. `server/server.js` scans `HOST_DIR` with `server/fileTree.js`, finding directories that contain `gtc.out`. The tree is cached and periodically rescanned.
2. The folder page requests `/fileTree`. `client/components/gtc-output-picker.js` displays, searches, and selects a simulation directory; submission posts to `/plot`.
3. The server creates or reuses a `GTCOutput` parser for the selected directory. Plot category requests load their corresponding parser; plot-data requests return Plotly figure descriptions. The batch-data endpoint groups multiple plot-data requests for summary views.
4. Parsers stream files line by line through `server/GTC-output-parser/PlotType.js` and return plot data through `PlotlyData`. Parsed results are cached per selected output.
5. Client code in `client/control/figure-manager.js` requests data, applies plot-specific processing, and renders figures. Snapshot spectra use the browser FFTE module; other calculations include History growth-rate/frequency analysis and time-unit conversion.

## Build and change guidance

- Edit browser sources in `client/`; `public/javascripts/` is generated by webpack. Do not make source changes only in generated bundles.
- `public/libs/plotly/plotly-custom.min.js` is built separately from `custom-plotly/`. The custom build includes only the trace types used by the app.
- `public/libs/ffte/` contains the browser loader and WebAssembly assets; `ffte/` is the FFTE submodule.
- Input descriptors under `client/gtc-input/` are checked against `server/input-parameters-schema.json`. Packaging commands run this validation before bundling.
- Runtime configuration is read from `.env`; use `.env_example` as the template. `HOST_DIR` selects the output root, `PORT` sets the listener, `LIMIT` caps cached outputs, and `SHOW_PATH` controls full-path display.
- `util/pack.js` copies release files to a temporary staging tree, normalizes its permissions, and writes a portable ustar archive without changing source permissions. Run `npm run pack` for a full build, or `node util/pack.js` when assets are already built; both produce `GTC-Visualization.tar.gz` with a `GTC-Visualization/` root. To recover an older read-only extraction on Linux, run `chmod -R u+rwX GTC-Visualization`, extract with `tar --delay-directory-restore -xf GTC-Visualization.tar.gz`, then repeat the chmod command. Packaging checks live in `test/pack.test.js`.
- Add or update focused tests under `test/` when requested or when needed to cover behavior changes. Test suites are available via `node --test` and the npm scripts above.
